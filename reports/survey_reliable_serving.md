# Serving a challenger you have not yet believed

Ahnaf An Nafee · 23 September 2026

## What this repository does

The serving half is a loopback HTTP service written against the standard library only. `reliability/server.py` builds a `RecommendationApp` and passes it to `handler_factory(app)`, whose handler is bound by `ThreadingHTTPServer(("127.0.0.1", args.port), ...)`; the server is reachable from the machine that started it and nowhere else. Run it with `python -m reliability.server --port 8899`.

**Two routes per request.** `RecommendationApp.recommend` scores the request twice in the same call. The first call, `self.model.top_k(history, self.baseline, 0.0, k)`, is the active candidate. The second, `self.model.top_k(history, self.baseline, self.alpha, k)`, is the challenger, and its ranking is returned in the `shadow` field whether or not it is allowed to serve. A neural challenger is scored the same way into `neural_shadow`. The response always carries `active`, `baseline`, `shadow`, `neural_shadow`, `method`, `fallback`, `gate_open` and `neural_gate_open`, so the route that served and the route that was waiting are both visible to the caller.

**Gate and fallback.** `method` becomes `"hybrid"` only when `gate_open` is true, the history is non-empty and no fallback fired; otherwise it stays the configured `baseline`. A challenger that raises is caught and recorded as `"challenger_unavailable"`, and `simulate_failure` in the POST body lets a test force that branch. A closed gate records `"validation_gate_closed"`, an empty history `"cold_history"`, and a history with no item present in `self.model.neighbors` `"unsupported_history"`. The neural route has its own reason codes, `"neural_unavailable"` and `"unsupported_history"`, and is promoted only when `neural_gate_open` is set and `neural_fallback` is null. The utterance route adds `"text_corpus_unavailable"`, `"nothing_to_match"` and `"phrase_matched_nothing"`, and `offer()` reports `"no_standing_sentence"`. Every failure path leaves the behavioural answer intact: the phrase layer is optional at start-up, and the process prints `phrase answers unavailable, behavioural route still serves` when the corpus cannot be loaded.

| Route field | Meaning in `reliability/server.py` |
| --- | --- |
| `method` | `hybrid` or `neural` when a challenger is being served, otherwise the selected baseline's own name (`recent` or `lifetime`) |
| `fallback` | `challenger_unavailable`, `validation_gate_closed`, `cold_history`, `unsupported_history`, or null |
| `neural_fallback` | `neural_unavailable`, `unsupported_history`, or null |
| `phrase_fallback` | `text_corpus_unavailable`, `nothing_to_match`, `phrase_matched_nothing`, or null |
| `shadow`, `neural_shadow` | challenger rankings scored and returned even while the gate is shut |

**Counters and latency.** Under a single `Lock`, `self.counts` accumulates `requests`, `baseline_routes`, `hybrid_routes`, `neural_routes`, `fallbacks`, `invalid_requests`, `phrase_requests`, `phrase_answers`, `sentences_held` and `offerings`. `GET /api/metrics` returns those counts plus `local_rank_ms` p50 and p95 taken from `self.latencies = deque(maxlen=1000)`, filled by a `perf_counter()` pair that starts before `top_k` and stops after it, with the scope note `in-process ranking only; no network or deployment capacity claim`. Request bodies are rejected before that window: 1–16,384 bytes, a field allowlist per endpoint, at most 200 history IDs of at most 128 characters each, `k` in 1–20; a rejection increments `invalid_requests` and answers 400.

**Nothing submitted is written out.** `Handler.log_message` is overridden to return immediately, with the comment `Never log submitted histories.` Spoken sentences live in `self.standing`, a plain list trimmed by `del self.standing[:-HELD_SENTENCES]` with `HELD_SENTENCES = 8`, and `MAX_PHRASE_CHARS = 400` bounds what one sentence may hold. `GET /api/ambient` answers from the last standing sentence without the caller submitting any wording. Row-level predictions are never serialized; `tools/release_check.py` enforces that, rejecting the JSON keys `user_id`, `parent_asin`, `history`, `target`, `ranked`, `weights` and `model` in tracked aggregate files via `scan_aggregate`, and rejecting any JSON array longer than 100 entries.

**Artifacts that refuse to load.** `reliability/bundle.py` writes `model.json.gz` plus a `manifest.json` carrying `{"schema": 1, "category", "catalog_items", "source_sha256", "model_sha256"}`, and refuses a directory that already exists. `load_bundle` re-hashes the payload and refuses on mismatch with distinct messages: `bundle manifest schema mismatch`, `bundle integrity mismatch`, `model schema mismatch`, `invalid popularity scores`, `invalid neighborhood source`, `invalid neighbor score`. It also cross-checks aggregates rather than trusting them — `len(lifetime)` against `manifest["catalog_items"]`, every popularity score finite and inside 0–1, no neighbourhood longer than 50 entries. A corrupted bundle stops the process instead of serving.

**CI as the boundary.** `.github/workflows/verify.yml` runs `python -m unittest discover -s tests -v` and `python tools/release_check.py` on Python 3.11 and 3.14, and a separate `neural-contracts` job installs CPU PyTorch on 3.12 and runs the same discovery. `tests/test_service.py` pins the shipped static preview to the Python model: `BundleTests.test_static_demo_matches_python_model` asserts `web/demo_bundle.json` reproduces `TITLES`, `PROFILES`, `gate_open` false, and the `lifetime`, `recent` and `neighbors` tables of `demo_model()` exactly, while `test_reload_parity_and_integrity` asserts `loaded.top_k(("atlas",), alpha=.75) == model.top_k(...)` and that appending one byte to `model.json.gz` raises an integrity error.

**Numbers the gate was asked about.** All from the committed reports: hybrid **0.008681** NDCG@10 against validation-selected recent popularity **0.008007** over **35,905** eligible positive-review requests, paired difference **+0.000674 [0.000040, 0.001338]** (`README.md`, `reports/transfer_note.md`); intervals from 1,000 user-cluster bootstrap draws, seed 20260922. The neural challenger reached **0.001411** unblended against recent popularity **0.010715** on validation, and **0.011774** at a 40% blend against the hybrid's **0.011969**, paired **−0.000195 [−0.000985, 0.000611]** — so `neural_gate_open` stayed false (`reports/neural_extension.md`). Measured local ranking p95 was **0.611 ms** on corrected Video Games and **0.760 ms** on Musical Instruments, baseline-plus-challenger scoring in process only, excluding HTTP, initialisation, disk loading, network, concurrency and sustained load (`reports/transfer_note.md`).

## What the literature says, grouped by the decision it informs

### What happens when the challenger cannot be reached

The degradation literature argues for naming the levels in advance and recording which one was entered, rather than treating any failure as an outage.

- [Building Secure and Reliable Systems, ch. 8](https://google.github.io/building-secure-and-reliable-systems/raw/ch08.html) — O'Reilly, 2022. Taken from this: a degraded mode is a designed state — determine and record levels of system degradation regardless of what set off the problem, load shedding returns errors instead of serving, throttling delays responses toward the deadline, controlled degradation may substitute a lower-cost alternative component, and resilient services ideally keep running, perhaps in a degraded mode.
- [Clipper: A Low-Latency Online Prediction Serving System](https://arxiv.org/abs/1612.03079) — arXiv preprint, 2016/2017. Taken from this: a serving layer sits between callers and models, holds a latency objective, and reacts to heavy query load by caching, batching and switching to a cheaper model — the same shape as a fallback to a cheaper validated route when the expensive one is unavailable.
- [The Coverage Illusion: From Pre-retrieval Routing Failure to Post-retrieval Cascades in a Production RAG System](https://arxiv.org/abs/2605.27220) — arXiv preprint, 2026. Taken from this: a production deferral policy over 20,000 query-workflow pairs found that routes the expensive path only where it pays — synthetic queries suggested LLM augmentation was needed for over 90% of queries to reach high retrieval coverage, while real traffic needed it for 27.8% — evidence that per-request route selection is a measured engineering decision, not a default.

### How a challenger earns traffic

- [Google SRE Workbook, "Canarying Releases"](https://sre.google/workbook/canarying-releases/) — O'Reilly, 2022 (Alec Warner, Štěpán Davidovič and others). Taken from this: canarying is defined as a partial and time-limited deployment of a change and its evaluation, which decides whether to proceed; canary against control is effectively an A/B testing process; not all release-related defects are detectable before real traffic hits the service; fast metrics such as query success reveal problems quickly while others need more time or a larger canary population; partial exposure conserves error budget.
- [Overlapping Experiment Infrastructure: More, Better, Faster Experimentation](https://research.google/pubs/overlapping-experiment-infrastructure-more-better-faster-experimentation/) — ALGO Conference, 2010. Taken from this: at Google scale almost every change that affects the user experience — including ranking and content-selection model changes — is evaluated experimentally, and the infrastructure alone is not enough: tooling and process are part of the system.
- [MLOps: continuous delivery and automation pipelines in machine learning](https://docs.cloud.google.com/architecture/mlops-continuous-delivery-and-automation-pipelines-in-machine-learning) — Google Cloud Architecture Center. Taken from this: model validation is the step where a model is confirmed adequate for deployment because its predictive performance is better than a certain baseline, and data validation decides whether to retrain or stop the pipeline — a gate expressed as a stop condition, exactly as `gate_open` is here.
- [Continuous Integration of Machine Learning Models with ease.ml/ci](https://arxiv.org/abs/1903.00278) — arXiv preprint, 2019. Taken from this: CI for models must state integration conditions with reliability constraints (their example: a one-point accuracy tolerance at 0.999 reliability under a bounded labelling budget), which is the general form of this repository's parity and gate tests.

### When the system should say nothing

- [Machine Learning with a Reject Option: A survey](https://arxiv.org/abs/2107.11277) — survey, journal version in Machine Learning, 2024. Taken from this: a learner may abstain when it is likely to be mistaken, rejection splits into ambiguity and novelty cases, and predictive and rejective quality are separate quantities to measure rather than one score.
- [Inductive Conformal Recommender System](https://arxiv.org/abs/2109.08949) — arXiv preprint, 2021. Taken from this: a recommender can output a set of recommendations each carrying a confidence value with a bound on the probability of a wrong recommendation, which is the calibrated form of the decision the fallback reasons here make uncalibrated.
- [Learning to Defer with Limited Expert Predictions](https://arxiv.org/abs/2304.07306) — arXiv preprint, 2023. Taken from this: deferral is a learned decision about which instances to hand to a second decision-maker, and learning it well needs enough evidence about the alternative's actual capability — the reason this repository keeps scoring the shadow route while the gate is shut.

### Whether an offline win should ship

- [Do Offline Metrics Predict Online Performance in Recommender Systems?](https://arxiv.org/abs/2011.07931) — arXiv preprint, 2020. Taken from this: comparing eleven recommenders across six controlled simulated environments, offline metrics correlate with online performance but the training and interaction dynamics change the relationship, so an offline ranking is not a transferable promise.
- [Identifying Offline Metrics that Predict Online Impact: A Pragmatic Strategy for Real-World Recommender Systems](https://arxiv.org/abs/2507.09566) — arXiv preprint, 2025. Taken from this: a model-agnostic, Pareto-front-based procedure for choosing which offline metrics to trust against an online experiment, needed precisely because no single offline metric is known in advance to track online impact.
- [Offline A/B testing for Recommender Systems](https://arxiv.org/abs/1801.07030) — arXiv preprint, 2018. Taken from this: counterfactual estimators estimate an uplift from logged data, and capped or normalised importance sampling has an unsatisfying bias-variance trade-off for personalised recommendation — so a paired offline interval like +0.000674 [0.000040, 0.001338] is a weaker claim than an A/B result.

### What a latency budget applies to

- [The Tail at Scale](https://research.google/pubs/the-tail-at-scale/) — Communications of the ACM 56 (2013) 74–80. Taken from this: systems responding within 100 milliseconds feel fluid and natural; keeping the tail of the latency distribution low gets harder as systems scale or as overall utilisation increases; temporary high-latency episodes that are unimportant at moderate size may dominate overall service performance at large scale.
- [Clipper: A Low-Latency Online Prediction Serving System](https://arxiv.org/abs/1612.03079) — arXiv preprint, 2016/2017. Taken from this: latency claims belong to a serving system measured under load, which is why the numbers in `reports/transfer_note.md` are scoped to in-process ranking and `metrics()` repeats the exclusion.
- [On-Device Recommender Systems: A Comprehensive Survey](https://arxiv.org/abs/2401.11441) — arXiv preprint, 2024. Taken from this: cloud recommender services gather interactions centrally and pay in resource consumption and response latency, which is the trade this repository accepts openly by scoring in one loopback process rather than moving scoring to the caller.

### How much of the catalogue to score per request

- [Deep Neural Networks for YouTube Recommendations](https://research.google/pubs/deep-neural-networks-for-youtube-recommendations/) — RecSys, 2016. Taken from this: the system is organised around the two-stage retrieval-then-ranking split, a candidate generation model followed by a separate ranking model, so a full-catalogue scorer is a design choice valid only while the catalogue is small.
- [Embedding-based Retrieval in Facebook Search](https://arxiv.org/abs/2006.11632) — KDD, 2020. Taken from this: an approximate-nearest-neighbour retrieval component is served inside a typical search system built on an inverted index, with ANN parameter tuning and full-stack optimisation, and gains reported from online A/B experiments.
- [SPANN: Highly-efficient Billion-scale Approximate Nearest Neighbor Search](https://arxiv.org/abs/2111.08566) — NeurIPS, 2021. Taken from this: billion-scale neighbour search is organised as an inverted index with centroids held for routing and posting lists stored on disk, latency and recall bought by reducing disk accesses — ANN confined to a candidate set, not a full scan.
- [Efficient and robust approximate nearest neighbor search using HNSW](https://arxiv.org/abs/1603.09320) — arXiv preprint, 2016 (journal version IEEE TPAMI). Taken from this: a multi-layer navigable-small-world graph gives logarithmic-complexity search with a heuristic that keeps high recall on clustered data.
- [Accelerating Large-Scale Inference with Anisotropic Vector Quantization](https://arxiv.org/abs/1908.10396) — ICML, 2020. Taken from this: quantisation error should be measured against the ranking loss that matters, aligning the loss with the largest inner products, since approximate scores only have to preserve order.
- [Billion-scale similarity search with GPUs](https://arxiv.org/abs/1702.08734) — arXiv preprint, 2017. Taken from this: brute-force full scans become viable only after deliberate engineering of k-selection and memory traffic, reaching 8.5× over the previous GPU state of the art — a reminder that a full-catalogue scan is a cost, not a free baseline.
- [Passage Re-ranking with BERT](https://arxiv.org/abs/1901.04085) — arXiv preprint, 2019. Taken from this: an expensive cross-encoder is affordable by scoring only the passages a cheaper first stage retrieved, which is the pattern a gate would exploit if the neural route were ever promoted.

### What must travel with the model, and what CI must prove

- [Model Cards for Model Reporting](https://arxiv.org/abs/1810.03993) — ACM FAccT, 2019. Taken from this: a model should ship with documented intended use, training data and evaluated performance, which is what a manifest states in machine-checkable form when it names schema, category, catalogue size and source hash.
- [Datasheets for Datasets](https://arxiv.org/abs/1803.09010) — arXiv preprint, 2018 (later CACM). Taken from this: absent standard documentation of composition and collection process has consequences, so documentation belongs to the artifact rather than to a person's memory.
- [MLOps: continuous delivery and automation pipelines in machine learning](https://docs.cloud.google.com/architecture/mlops-continuous-delivery-and-automation-pipelines-in-machine-learning) — Google Cloud Architecture Center. Taken from this: testing an ML system needs data validation, trained model quality evaluation and model validation on top of unit and integration tests, and containerised components exist to make code reproducible between development and production.

## What the literature says to expect here

| Implemented behaviour | What the literature predicts | What this repository has measured |
| --- | --- | --- |
| `fallback = "challenger_unavailable"` returns the validated baseline list | A degraded mode should be a designed, named state that still serves, with the reason recorded regardless of trigger | `fallbacks` counter increments on any reason code; the response still carries `active` and `baseline` |
| Challenger scored into `shadow` while `gate_open` is false | A challenger needs evidence produced on live-shaped traffic before it takes traffic; capability must be observed, not assumed | The neural challenger scored 0.001411 unblended against recent popularity 0.010715 on validation, and −0.000195 [−0.000985, 0.000611] paired against the hybrid at a 40% blend — gate left shut |
| `method == "hybrid"` only when the gate is open, history non-empty and every reason null | Promotion should be a gate evaluated against a baseline, with partial exposure rather than a switch | The gate is a user-cluster bootstrap on validation whose lower 95% percentile endpoint must exceed zero; the test-period result was hybrid 0.008681 vs baseline 0.008007 over 35,905 requests, paired +0.000674 [0.000040, 0.001338] |
| `local_rank_ms` p50/p95 over `deque(maxlen=1000)` with an explicit scope string | Latency budgets are about the tail under real load; an in-process number is not a service-level claim | 0.611 ms p95 (corrected Video Games), 0.760 ms p95 (Musical Instruments), excluding HTTP, initialisation, disk loading, network, concurrency, sustained load |
| Full-catalogue `top_k` in pure Python over 22,976 train-known items (Video Games) and 22,753 (Musical Instruments) | Below some catalogue size a scan beats the machinery of an index; above it, retrieval narrows before ranking | Sub-millisecond p95 at these catalogue sizes, so no ANN layer is justified yet |
| `load_bundle` raises on manifest schema, sha256 or aggregate-count mismatch | Artifacts should be provenance-checked and refuse to start rather than serve an unknown model | `tests/test_service.py` asserts one appended byte raises an integrity error and that reloaded scores match |
| `unittest discover` on 3.11 and 3.14 plus `tools/release_check.py` in CI | Reproducibility and boundary checks belong in the gate that blocks the merge, not in a release ritual | `release boundary passed: N source, documentation and aggregate files` on every run |
| `test_static_demo_matches_python_model` pins `web/demo_bundle.json` to `demo_model()` | A second implementation surface must be proven equivalent to the model it claims to show | Equality of `TITLES`, `PROFILES`, `gate_open`, `lifetime`, `recent` and `neighbors` |
| `Handler.log_message` returns; sentences held in `self.standing`, trimmed to 8 | Inferences drawn from evidence already held stay cheap and local when they are not persisted | No submitted history is logged or persisted; `held` reports the in-process count only |

Three expectations are only partly met. The reject-option and conformal literature expects the abstain decision itself to be measured; here `cold_history` and `unsupported_history` choose a route, never silence, and the service always returns `k` items — 1,288 requests in the cohort study had no history at all and 1,573 validation rows in Musical Instruments have an empty history. The canary literature evaluates against metrics attributable to a service indicator; the counters exist but nothing consumes them across a rollout, since there is no rollout. And the offline-online literature treats an offline paired interval as a proxy: `reports/transfer_note.md` already shows how much headroom the metric misses, with 12,305 of 35,905 test targets in Musical Instruments and 22,051 of 35,562 in Video Games unrecoverable by any ranking restricted to the train-known catalog.

## Open questions

1. Which offline statistic, if any, would have predicted that the neural challenger was worth promoting? The gate requires a lower 95% percentile endpoint above zero, a rule chosen for its conservatism rather than calibrated against any observed online outcome.
2. What p99 does the in-process ranking window hide? `metrics()` reports p50 and p95 over the last 1,000 requests, while the tail-at-scale literature says the episodes that matter live further out and grow with utilisation.
3. Does a `fallbacks` rate of any size matter to a caller? No consumer of `/api/metrics` exists, so the reason codes are currently a diagnostic surface rather than a control.
4. Would a shadow route ever disagree with the active route in a way the counters cannot see? `shadow` is returned per request but never compared against `active` across requests, so disagreement rate — the quantity a promotion review actually wants — is unmeasured.
5. What does an ANN layer cost at this catalogue size? With p95 below a millisecond at 22,976 train-known items, the retrieval literature argues the scan is the right choice now, but it gives no threshold for when that inverts for a full-catalogue scorer in pure Python.
6. How should the manifest schema evolve? `schema: 1` refuses everything else outright, which is the safe direction but gives no path to a compatible additive change without a second loader.
